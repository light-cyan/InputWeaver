# 运行行为与限制

[文档首页](README.md)

这篇说明目标切换、暂停、多个动作同时执行和资源不足怎样影响程序。其中目标选择、前台窗口和排除应用的说明适用于 Windows 执行器。具体语言写法见[输入映射与规则](rules.md)和[动作与流程控制](actions.md)，Windows 支持的按键与鼠标操作见[Windows 执行器](windows.md)。

## 目标怎样选择

源码的 `TARGET` 提供默认目标；界面的 Target 配置或命令行选项可以覆盖它。指定应用时，接受可执行文件名或绝对路径；全局运行使用 `GLOBAL`、界面中的 `Global` 或命令行的 `--target-global`。

Windows 按不区分大小写的方式比较进程名称和规范化后的路径。只有一个匹配实例时选中它；多个实例匹配时优先选择处于前台的实例，仍有歧义时等待可明确选择的实例。选中后绑定具体进程，切换到另一个同名进程的前台窗口不会更换绑定；绑定进程退出后才重新寻找目标。

应用限定运行需要目标拥有前台窗口；鼠标输入还会检查指针位置是否属于目标。目标尚未出现时，执行器继续等待并观察输入，Debug 和物理退出规则可以工作，普通映射和动作等到目标可用后开始接收新输入。

## 排除应用

`--exclude` 指定一个可执行文件名或绝对路径。排除应用处于前台时，普通规则和映射不响应输入，物理输入放行，也停止新的按键和鼠标输出。这个条件同时适用于应用目标和全局目标。

退出规则优先于排除判断，命中时仍会接管输入并停止执行器；模拟运行时物理输入始终放行。

宿主为它启动的每个执行器自动设置 `--exclude InputWeaverTUI.exe`，方便编辑和停止程序。为释放已经按住的键而产生的清理输出仍会执行。

## 切换窗口和重启目标

目标失去前台资格时，正在执行或等待的动作取消，已建立的映射清理，程序持有的输出释放。重新切回目标后，由新输入触发新的工作。

例如，按住 A 建立了 `A -> B`，随后切到其他窗口，输出 B 会释放。切回目标时先松开 A，再按一次，才能建立新的映射。

目标进程退出时，执行器清理相应工作并继续等待它重新出现。重新找到目标后，使用同一个运行中的程序：用户变量、数组和 `PAUSE` 状态保留，已取消的动作需要重新触发，计量器统计重新建立。

## 暂停、停止和重新运行

| 操作 | 动作和输出 | 变量、数组和随机序列 |
| --- | --- | --- |
| `PAUSE` 状态切换 | 取消已有任务，清理映射并释放输出 | 保留 |
| 目标资格丢失 | 取消目标相关工作并释放输出 | 保留 |
| 停止执行器 | 结束当前运行并释放输出 | 当前运行结束 |
| 再次运行程序 | 从源码声明的初始状态开始 | 重新初始化 |

`PAUSE` 的值为 `on` 时普通规则启用，为 `off` 时暂停；在源码中通过 `pause` 规则切换。停止可以使用退出规则、界面中的 `X`，或托盘的 `Exit InputWeaver`。[操作方法](tui.md)

## 启动时已经按住的键

执行器启动时会读取程序所使用控制的物理状态。初始化让条件能够判断哪些键已经按住，但这次初始化本身不会产生一次 `down` 触发。

某些原始控制只能从后续事件确认状态。这类来源先放行输入，观察到物理释放后再建立基线。测试新程序时，可以先松开相关按键，再进行一次完整的按下和松开。

## 同时触发多条规则

同一次输入的所有规则条件读取相同的变量和数组状态。匹配完成后，命中规则的非空动作按源码顺序加入待执行列表，每条规则的这次执行称为一个任务。

一个任务会继续执行相邻动作，直到完成、取消、遇到正时间等待，或循环返回下一轮时让出执行机会。其他任务可以在这些位置穿插执行，并读写共享变量。

`wait(0ms)`、零间隔和零时长 `tap` 会立即继续。循环让出执行机会也不代表已经等待了一段固定时间；需要控制输出节奏时，写明确的正时间 `wait`。

每个任务负责释放自己按住的输出。多个任务持有同一个键时，最后一个持有者释放后才发送最终松开。这能保持共享输出的一致状态，也意味着重叠的点击可能合成一次按住。

## 模拟运行检查什么

模拟运行保留输入观察、规则匹配、任务执行、变量修改、暂停、退出和调试。物理输入始终放行，键盘和鼠标输出只模拟成功。

连续的鼠标输出会使用模拟指针位置计算下一步；新的物理鼠标输入会重新对齐模拟位置。`Mouse.x` 和 `Mouse.y` 仍显示实际指针位置。

`exec` 仍需要本次运行授权，通过检查后只模拟成功。Debug 中的 `DROP` 和统计中的接管数，表示正常模式下的处理决定。[调试与排错](debugging.md)

## 表达式和动作出错

除以零、数组索引越界、非有限数字和时间溢出等求值错误，会按出错位置决定影响范围。编译时能够确定的常量错误会报告编译诊断。运行时，计量器完成记录缺失有专门处理，其余求值错误按所在位置区分：

| 出错位置或情况 | 运行时处理 |
| --- | --- |
| 访问尚无完成记录的 `@name` 字段 | 条件不匹配，动作中的当前任务结束，并报告诊断；`@name.valid` 本身可正常读取 |
| 普通规则、完整映射、暂停规则或退出规则的条件求值 | 报告诊断，并请求停止整个执行器 |
| 标量 `set` 的右侧表达式、`wait` 的时间、`if` 或 `while` 的条件、`repeat` 的次数 | 报告诊断，并请求停止整个执行器 |
| 数组动作中的索引或值表达式、空数组 `pop`、数组增长失败 | 报告诊断，结束当前任务并释放它持有的输出；其他任务继续运行 |
| `release` 释放当前任务未持有的控制 | 报告诊断，结束当前任务并释放它仍持有的输出；后续动作不再执行 |
| `move_by`、`move_to`、`scroll` 或 `scroll_horizontal` 的参数求值 | 报告诊断，结束当前任务并释放它持有的输出；其他任务继续运行 |
| 动态计量周期求值失败或周期不是正值 | 报告诊断，清理该计量器的未完成进度，并在后续符合条件的输入到来时重试；最近完成记录保留 |

请求停止执行器会取消全部任务、清理映射并释放程序持有的输出。仅结束当前任务时，之前已经完成的变量和数组修改仍然保留；再次启动执行器则从声明的初始状态开始。

同一种错误可能有不同的影响范围。例如，`set(count, values[index])` 的数组读取发生在标量赋值表达式中，索引越界会请求停止执行器；`set(values[index], 1)` 的索引错误属于数组动作，只结束当前任务。用除数检查、索引范围、数组长度和 `@name.valid` 保护相关访问。[诊断定位](debugging.md)

## 资源上限

程序使用的控制、变量、规则和同时执行的任务都有上限。启动时已超限的程序会报告所需数量与可用数量；运行中超限可能导致新触发的动作未执行、当前任务取消，或整个执行器停止。

下面列出排查复杂宏时较常遇到的上限：

| 项目 | 默认上限 |
| --- | ---: |
| 使用的控制数 | 4096 |
| 每种标量类型的变量数 | 4096 |
| 数组数量 | 4096 |
| 所有数组占用的总内存 | 64 MiB |
| 用于映射的不同来源控制数 | 4096 |
| 同一事件的普通规则数，包括完整映射的按下规则 | 256 |
| 同一事件的退出规则或暂停规则数 | 各 64 |
| 同时存在的动作任务 | 256 |
| 每个任务持有的输出控制数 | 256 |
| 每个任务在实际等待前的普通输出数 | 4096 |
| 普通输出速率 | 每秒 2048 次 |
| 单个物理鼠标报告完成的计量周期数 | 1024 |

新触发的任务或待处理工作超出容量时，同一次事件匹配到的任务和映射操作会一起被拒绝，并报告 `TransactionCapacity`；如果这是物理输入事件，该输入放行。原始鼠标事件与每次 tick 分别处理，某次 tick 的工作被拒绝不会撤销其他已经接受的工作，也不会改变原始鼠标报告的接管决定。遇到这种情况，减少同一输入触发的规则数量，或检查是否有大量尚未结束的任务。

单个物理鼠标报告产生超过 1024 个完成周期时，会报告 `TransactionCapacity` 并请求停止整个执行器，取消全部任务并释放输出，该报告放行。

同一来源控制的多条条件映射按一个来源计数。例如 `A -> C when LCtrl == held;` 和 `A -> B;` 合计使用一个映射来源；它们同时作为两条按下规则计入 `A:down` 的规则容量。`A` 与 `Keyboard.A` 这样的别名合并计数。

按下、重复按下、鼠标移动和滚动计入普通输出次数；用于清理的松开不占用这一额度。连续动作或循环达到执行上限，或连续输出过多时，当前任务会取消。实际等待一段正时间后，会重新计算该任务的连续执行和输出次数；`wait(0ms)` 和单纯进入下一轮循环都不会重新计算。普通输出速率超限时，取消产生超额输出的任务或映射并清理其输出。

如果看到 `TaskBudgetExceeded`，检查长动作和循环里的等待；看到 `OutputRateExceeded`，降低输出频率；数组增长被拒绝时，检查是否持续追加而没有清理。[日志定位](debugging.md)

## 查看失败信息

启动错误中的 `code` 表示失败类别，`subject` 表示具体限制项，`required` 和 `available` 分别表示程序需求和执行器容量。

运行中的问题看 Debug 的 HEALTH、ACTION EXECUTIONS 和 Console；需要保留现场时启用日志。输入和动作的详细检查步骤见[调试与排错](debugging.md)。
