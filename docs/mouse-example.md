# 鼠标 meter 示例与 Debug 阅读说明

将 `examples/mouse-meters.weave` 导入程序库，启用 Trace and Debug 后运行。示例目标为 `Code.exe`；测试时保持 Code 在前台，鼠标位于编辑区。meter 从符合目标条件的鼠标输入开始累计，移动转滚动功能初始关闭。按住 CapsLock 再按数字键执行示例命令；示例在 Code 中正常启用时会消费 CapsLock 的按下和释放，让它作为命令前缀使用。

## 操作对照

| 输入 | 行为 |
| --- | --- |
| 移动鼠标 | `path` 每累计 24 像素完成一个周期，`fine` 每 8 像素完成一个周期，`pulse` 每持续移动 100ms 完成一个周期。 |
| 纵向／横向滚轮 | `vertical` 每累计正向或反向一格完成一个周期；`horizontal` 的周期为四分之一格。原生滚动继续生效。 |
| 按住左 Shift 操作鼠标 | 分别增加原始移动、纵向滚轮和横向滚轮事件计数。 |
| CapsLock+1／CapsLock+2 | 保存实际鼠标位置／回到保存的位置。 |
| CapsLock+3 | 移动出边长 12 像素的小正方形；第一条边使用 24 次半像素相对移动请求。 |
| CapsLock+4 | 输出四分之一格纵向滚动，等待后输出四分之一格横向滚动。 |
| CapsLock+5 | 在 24 和 48 之间切换距离周期；新值在下一个周期开始时生效。 |
| CapsLock+6 | 重启全部五个 meter，清除当前累计和最近完成周期；用户声明的计数变量保留。 |
| CapsLock+7 | 将当前 Mouse 和 meter 字段逐项保存到示例的数组与采样变量中。 |
| CapsLock+8 | 在等待 400ms 前后分别读取本任务选定的已完成 `path` 周期。期间继续移动可对比固定快照与实时状态。 |
| CapsLock+9 | 开关移动转滚动功能，并重启 `path`。每次完成周期后，根据净位移中较大的轴及其正负选择滚动方向。 |
| CapsLock+0 | 在 100ms 和 250ms 之间切换持续移动周期。 |
| Pause | 暂停／恢复普通规则；状态切换会取消任务并清除 meter 统计。 |
| CapsLock+Esc | 停止执行器。 |

## Debug 的四个区域

| 区域 | 显示内容 | 更新逻辑 |
| --- | --- | --- |
| EVENTS | 键盘和鼠标按键的输入历史。 | 每次输入追加记录，保留最近 512 条。 |
| STATE | 用户变量、数组、当前按下控制、Mouse 观测、各 meter 的当前与最近完成周期。 | 更新已有项目的值；Mouse 和全部 meter 由执行器约每 50ms 发送一次整体快照。 |
| ACTION EXECUTIONS | 已匹配并进入执行管线的规则及其状态。 | 每次规则执行建立一条记录，随后更新执行结果，保留最近 256 条。 |
| HEALTH | 连接、捕获、数据可信性、Dry-run、PAUSE、故障和最近运行时问题。 | 随会话和运行状态变化更新；执行器结束后显示最终快照状态。 |

EVENTS 和 STATE 位于上方，合计使用标题与 HEALTH 之间约 60% 的高度；下方 ACTION EXECUTIONS 使用剩余约 40%。EVENTS 最多占 60 列，其余宽度留给 STATE。在最小 80 列窗口中，EVENTS 占 53 列、STATE 占 27 列；HEALTH 固定占四行。

使用方向键选择区域，按 Enter 进入后使用方向键、PageUp、PageDown、Home、End 滚动，Esc 返回区域选择。STATE 内容会按宽度重新排版，完整项目之间间隔两个空格；单个项目过长时换行。End 跟随区域底部，Home 查看开头；滚动只改变查看位置，数值仍继续更新。

### STATE 中为什么有许多相同或接近的鼠标坐标

STATE 按顺序显示全部用户标量、全部数组、当前按下控制，再显示 Mouse 和 meter。示例为了演示字段读取声明了保存位置、采样数组和计数变量，因此这些项目也会全部出现，包括初始值为 0、off 的项目。

只有 `[Mouse ...]` 表示全局实际鼠标的当前观测。其余坐标属于各自的统计周期或示例保存值：

| 项目 | 坐标代表什么 | 何时改变 |
| --- | --- | --- |
| `Mouse pos(x,y)` | 系统当前实际鼠标位置。 | 捕获期间持续采样。 |
| `path`、`fine`、`pulse` 的 `start(x,y)` | 该 meter 当前周期的起点。 | 当前周期开始时确定，后续累计保持这个起点。 |
| 移动 meter 的 `pos(x,y)` | 当前周期最后纳入的移动位置。 | 该 meter 纳入新的有效移动时更新。 |
| 滚轮 meter 的 `pos(x,y)` | 该 meter 最近纳入的滚轮输入发生位置。 | 对应方向的新滚轮输入到来时更新。 |
| `@path` 等完成项目中的坐标 | 该 meter 最近完成周期的起点或终点；滚轮只有发生位置。 | 新周期完成时整体替换；重启后显示 `empty`。 |
| `savedX`、`savedY` | 示例保存的鼠标位置。 | 按 CapsLock+1 时赋值。 |
| `live`、`current` 数组 | 示例逐项读取并保存的 Mouse／当前周期字段。 | 按 CapsLock+7 时赋值。 |
| `before`、`after` 数组 | 同一个任务选定的已完成周期字段。 | 按 CapsLock+8 后，在等待前后分别赋值。 |

多个移动 meter 会处理同一条物理移动，所以当前终点经常相同，但周期起点、累计进度和最近完成位置可以不同。meter 尚未建立起点时，当前视图的起点和位置都使用当时观测到的鼠标位置，周期和进度为 0；这时尤其容易看到重复坐标。示例的 `live` 只是普通数组名称，保存后会保留原值，下一次按 CapsLock+7 才重新读取。

从 Code 切换到 Debug 窗口会让目标失去前台资格，运行时随之取消任务并清除 meter 统计。Mouse 的全局观测仍继续，所以尚未重新开始的各个 meter 坐标会一起跟随实际鼠标，完成项目则显示 `empty`。观察实时周期时，可把两个窗口并排摆放，保持 Code 获得焦点；也可在 Code 中先用采样快捷键保存字段，再切回 Debug 查看保留的用户变量和数组。

这些项目在每次快照到来时原位更新。一个 meter 固定对应当前视图和最近完成视图两个项目，多次完成周期会替换最近完成视图。

### 读懂 Mouse 项目

```text
[Mouse pos(103,200) d(3,0) wheel(0,0) moving idle(0.012s)]
```

| 部分 | 含义 |
| --- | --- |
| `pos(103,200)` | 当前实际鼠标坐标，顺序为 x、y，单位为物理屏幕像素。 |
| `d(3,0)` | 最近一次物理鼠标数值输入中的 dx、dy。这里表示向右 3 像素。 |
| `wheel(0,0)` | 同一次数值输入中的横向、纵向滚轮量，单位为标准滚轮格。 |
| `moving` | 最近有效物理移动距离现在尚未达到 `MOUSE_IDLE_TIMEOUT`；达到后显示 `idle`。 |
| `idle(0.012s)` | 距离最近一次有效物理移动过去 0.012 秒；始终以秒显示，尚未移动时从程序激活开始计时。 |

移动或滚轮输入会整体替换 `d` 和 `wheel` 对应的四个分量：移动输入将两个滚轮量设为 0，滚轮输入将 dx、dy 及另一个滚轮轴设为 0。键盘和鼠标按键输入保留这四个最近值；停止移动本身也保留它们，因此判断是否仍在移动应读 `moving` 或 `idle_time`。STATE 的 Mouse 数字使用六位有效数字显示，运行时计算保留原始精度。

### 读懂 meter 项目

```text
[path 3/24 start(100,200) pos(103,200) d(3,0)]
[@path 24 start(76,200) pos(100,200) d(24,0)]
[pulse 20ms/100ms start(100,200) pos(103,200) d(3,0) dist(3)]
[vertical -0.25/1 pos(103,200)]
[@vertical empty]
```

`path 3/24` 表示当前距离周期已经累计 3 像素，周期阈值为 24 像素，还差 21 像素。`start` 是起点，`pos` 是当前周期纳入的末端位置，`d` 是该周期累计的有符号净位移。距离进度累计每段移动的长度，来回移动也会增加；净位移则会相互抵消。

`@path 24` 表示最近完成的距离周期累计了 24 像素。图示周期从 `(76,200)` 到 `(100,200)`，净位移为 `(24,0)`。它保留到下一次完成或重启为止。

`pulse 20ms/100ms` 表示当前连续移动周期累计了 20ms，当前采用的周期为 100ms。`dist(3)` 是这段时间内累计的路径长度。时间进度随连续有效移动报告推进；连续移动要求相邻有效报告间隔小于 `MOUSE_IDLE_TIMEOUT`。

`vertical -0.25/1` 表示当前纵向滚轮净累计为负四分之一格，周期阈值为一格；反向滚动先抵消余量。`@vertical empty` 对应 `@vertical.valid == off`，表示尚无可读取的完成周期。

周期阈值在每个周期开始时锁定。因此修改 `stride` 后，变量可以立即显示 48，而当前 `path` 仍显示 `3/24`，等下一个周期开始才采用 48。各 meter 独立持有自己的进度和周期相位；同一 meter 的多条订阅规则共享同一个周期。

### EVENTS：输入历史

```text
16:28:38.582  A                 down     PHY   PASS
```

各列依次是捕获时间、控制名、按下／释放、来源和处置结果。`PHY` 表示物理候选输入，`SYN` 表示注入来源，`INIT` 表示捕获开始时已经按下的控制快照。`PASS` 表示逻辑放行，`DROP` 表示逻辑消费，`-` 表示该项不适用；Dry-run 保留逻辑决定的显示，同时实际放行物理输入。`AGAIN` 表示已按下时再次收到按下，`NO-DOWN` 表示释放前缺少已知按下。

移动、滚轮和 meter tick 保留在独立的内部关联历史中，用于找回动作的准确触发来源；EVENTS 的可见历史由键盘和鼠标按键占用。捕获也能观察目标程序之外的输入；普通规则是否执行另由目标资格和 PAUSE 决定。

### ACTION EXECUTIONS：规则执行历史

```text
#17  EVENT 16:28:38.582  MATCH 16:28:38.582  path (tick)
  AS   always
  ACT  set(pathCycles, pathCycles + 1)
```

`#17` 是本次规则执行编号；`EVENT` 是触发输入的捕获时间，`MATCH` 是建立执行记录的时间。`path (tick)` 表示由 `path` 完成周期触发。原始鼠标规则则显示 `Mouse (move)`、`Mouse (wheel)` 或 `Mouse (horizontalwheel)`。`AS` 是源码条件，无条件时显示 `always`；`ACT` 是源码动作，并非每一步动作执行后的计算结果。

一条规则的一次执行对应一条记录；一条规则中的多个动作放在同一个 ACT 中。同一周期如果命中两条订阅规则，会显示两条执行记录。示例中的 `fine:tick` 每累计 8 像素就运行一次，所以持续移动时 ACTION EXECUTIONS 仍可能快速增加，这是示例真实执行的规则记录。

执行条目通过颜色表示状态：运行中为青色，完成为深绿色，失败为红色，取消为黄色。STATE 中的 `@名称` 始终表示采样时最近完成的周期；任务表达式中的 `@名称` 则固定为触发该任务时选定的周期，即使经过 `wait` 也保持不变。两者在任务等待期间可能不同。

### HEALTH：捕获与执行器状态

HEALTH 显示连接和捕获是否正常、快照是否可信、是否启用 Dry-run，以及 PAUSE、故障、运行时问题数量和最近问题。当前语言中 `PAUSE=on` 允许普通规则分派，`PAUSE=off` 暂停普通规则。执行器结束后显示退出代码，以及 `Complete snapshot` 或 `Best-effort snapshot`。

Debug 中按 C 停止捕获或开始新一轮捕获，只控制观测。新捕获重建显示历史和状态视图，并保留运行时原有变量、数组和 meter 相位。按 X 停止执行器；目标丢失、Pause 切换等运行时取消会清除 meter 统计。

## 示例采样数组

| 数组 | 字段顺序 | 采样方式 |
| --- | --- | --- |
| `live` | x、y、dx、dy、wheel_x、wheel_y | CapsLock+7 逐项读取 Mouse。 |
| `current` | start_x、start_y、x、y、dx、dy、distance、progress | CapsLock+7 逐项读取当前 `path`。 |
| `before`、`after` | start_x、start_y、x、y、dx、dy、distance、period | CapsLock+8 读取该任务选定的 `@path`，分别在等待前后保存。 |

`sampledPeriod`、`sampledRemaining`、`sampledIdle`、`sampledMoving`、`sampledTimeProgress`、`sampledTimeRemaining` 也由 CapsLock+7 赋值。普通变量和数组随赋值同步，Mouse／meter 快照则按采样节奏同步；多个 `set` 逐项执行，应将这些数组理解为示例采样值。

先在 Code 内移动一段距离，让 `path` 完成周期，再按一次 CapsLock+8，继续移动并等待任务完成。此时 `snapshotReady=on`，`before` 和 `after` 应相同；STATE 中的 `path` 与 `@path` 则可以继续变化。等待期间用 CapsLock+6 重启 meter 也会保留该任务已经选定的快照。验证期间保持 Code 在前台：目标丢失或 Pause 切换会取消等待任务。

## 测试时需要注意

示例将 `MOUSE_IDLE_TIMEOUT` 设为 80ms。普通停顿保留距离和滚轮余量，但连续移动中断达到 80ms 时会清除尚未完成的时间周期。暂停或目标资格丢失引起的取消会重置 meter；用户计数变量继续保留。

鼠标输出按动作执行时的 Code 目标资格检查。测试保存位置、回到位置和小正方形时，让原点及目标都留在 Code 内。横向滚动可在关闭自动换行的长代码行上观察。程序输出会改变实际指针位置，但只有物理输入计入这些 meter 的移动统计。

Debug 的 Skip Simulated Input 启用 Dry-run：规则和动作准备照常执行，鼠标输出使用模拟位置，实际指针与原生滚轮效果保持不变；STATE 的 Mouse 坐标仍来自实际指针。
