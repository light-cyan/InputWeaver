# 键盘运行安全指南

本文说明编译型键盘映射程序的启动方式、安全边界、停止方法和日志检查方法。命令均在仓库根目录的 `cmd.exe` 中运行。

所有当前固定容量、任务预算、日志上限和控制台统计字段集中记录在 `docs/runtime-boundaries.md`。

## 构建、编译与运行

先构建编译器和执行器，再把 `.weave` 源文件编译为 `.weavec`：

```bat
script\build_compiler_tests.bat
script\build.bat
bin\InputWeaverCompiler.exe validate path\to\config.weave
bin\InputWeaverCompiler.exe compile path\to\config.weave path\to\config.weavec
```

不包含 `exec` 动作的程序使用以下命令启动：

```bat
bin\InputWeaver.exe --program path\to\config.weavec
```

包含 `exec` 动作的程序默认不能激活，必须在本次启动中显式授予进程启动权限：

```bat
bin\InputWeaver.exe --program path\to\config.weavec --allow-exec
```

`--allow-exec` 只对当前编译程序运行生效，并且只能和 `--program` 一起使用；没有这个选项时，执行器会在安装输入钩子之前拒绝需要启动进程的程序，也不会解析可执行文件或调用系统进程创建接口。

可以用 `--target <exe-name-or-absolute-path>` 把本次运行覆盖为目标进程模式，或用 `--target-global` 把本次运行覆盖为全局模式；两个选项互斥。也可以用 `--log <jsonl-path> --trace-input` 记录运行时、安全状态、物理输入和输出注入信息。

## 目标窗口切换

目标限定程序只在选定进程拥有前台窗口时接收规则事件。目标失去前台后，InputWeaver 会推进取消代次、取消仍在运行或等待的任务、清除活动映射并发布所有已持有输出键的释放事件；物理输入在目标不可用期间直接放行。

目标重新回到前台后，编译程序继续可用，但只处理之后出现的新物理事件。一个在目标失去前台前已经按下并一直保持的来源键不会产生新的映射按下；必须先观察到它的物理释放，再次按下才会建立新的映射生命周期。

输出键的按下与重复在进入输出队列前和实际注入前都会重新检查目标资格。释放事件属于安全清理流量，不受目标资格、旧取消代次或普通输出速率上限阻挡。

目标进程退出时，当前会话先取消执行并清理输出所有权，然后结束；外层启动流程会继续等待符合目标选择条件的进程重新出现。

## 启动时已经按下的键

执行器会在普通事件分派开始前查询编译程序使用的键盘控制状态。映射、条件、PAUSE 规则和退出规则引用且具有稳定 Windows 查询方式的键盘控制会分别初始化，初始化本身不会匹配规则、创建任务、建立映射或生成输出。

如果一个事件来源只有原始事件身份而无法可靠查询初始状态，它会以“尚未同步”状态启动。这个来源的事件会直接放行，直到执行器观察到一次物理释放；释放建立空闲基线，下一次新按下才可以进入规则分派。

用于 `[held]` 或 `[idle]` 物理状态表达式的控制必须具有可靠的初始状态查询能力，否则程序会在安装钩子之前激活失败。

## 固定安全上限

执行器在激活时把编译产物中精确派生的需求与固定运行容量比较。默认容量如下：

| 安全项 | 默认容量 |
| --- | ---: |
| 单个事件的退出规则数 | 64 |
| 单个事件的 PAUSE 规则数 | 64 |
| 单个事件的普通规则数 | 256 |
| 单个事件的条件指令步数 | 4096 |
| 单个事件的映射操作数 | 64 |
| 单个任务在有效挂起前执行的动作指令数 | 65536 |
| 单个任务在有效挂起前发布的普通输出数 | 4096 |
| 持续就绪调度量子数 | 16 |
| 持续就绪后的退避时间 | 1 毫秒 |
| 普通输出速率 | 每 1 秒 2048 个按下或重复转换 |

超过同步事件容量的程序在钩子安装前被拒绝，错误信息同时包含所需值和可用值。任务的指令或输出预算耗尽时，只取消违规任务并释放该任务持有的输出；一次真正进入未来单调时钟时刻的正时长挂起会重置任务进度区间，`yield`、循环回边、零时长 `wait` 和零时长动作间隔不会重置预算。

键盘钩子读取退出条件、PAUSE 和用户变量时采用非阻塞锁；如果后台任务恰好正在独占更新相关状态，本次物理事件会直接放行，不会等待后台任务完成。没有 PAUSE 语句的程序不建立 PAUSE 控制查询路径，内蕴 `PAUSE` 保持为 `on`。任务线程的唤醒使用非阻塞计数信号，取消、关闭或新事务不会要求键盘钩子等待调度线程。

持续就绪任务达到调度阈值后，工作线程会进行有上限的等待；新输入、目标资格变化、取消、关闭和退出规则都会立即唤醒它。控制台结束指标中的 `scheduler_backoffs` 可用于确认退避实际发生。

普通输出达到速率上限时，执行器取消产生超额输出的任务或映射并立即清理其所有权。输出键的释放不计入普通输出额度，因此速率耗尽不会阻止必要的键抬起。

## 退出控制

可以用顶层 `exit` 语句声明退出事件及其可选条件：

```weave
exit F12:down when (LCtrl[held] or RCtrl[held]) and (LShift[held] or RShift[held]);
```

退出规则只接受物理输入，并在目标前台检查、PAUSE 控制、映射和普通规则之前求值；匹配后消费当前事件并停止活动程序。可以声明多条退出规则；只要源码存在任意 `exit`，编译器就只写入源码中的退出规则。源码没有 `exit` 时，编译器把上面的任意侧 Ctrl、任意侧 Shift 和 F12 规则作为默认规则写入 `.weavec`。退出条件引用且在启动前已经按下的修饰键会通过编译产物的控制需求初始化。

正常停止后应确认会话指标中的 `injection_failures=0` 和 `runtime_diagnostic_drops=0`，并以程序完全刷新和关闭日志后输出的 `Diagnostic log stopped.` 指标为准，确认三类外层日志丢弃计数均为 `0`、`jsonl_truncated=false`，同时确认没有键保持在按下状态。

## 安全日志

以下命令同时记录安全状态和完整物理输入轨迹：

```bat
bin\InputWeaver.exe --program path\to\config.weavec --log path\to\run.jsonl --trace-input
```

JSONL 中与第四阶段安全边界直接相关的运行时事件包括：

- `TargetEligibilityChange`：`detail=0` 表示目标暂时不可用，`detail=1` 表示目标重新可用。
- `PhysicalStateSynchronization`：`detail=0` 表示来源以尚未同步状态启动，`detail=1` 表示物理释放已经建立基线。
- `TaskBudgetExceeded`：`detail=1` 表示任务指令预算耗尽，`detail=2` 表示任务输出预算耗尽。
- `OutputRateExceeded`：普通按下或重复输出达到当前速率窗口上限。
- `Cancellation`：记录 PAUSE、目标资格变化、目标退出、退出规则、关闭和运行故障引发的取消代次。

任务预算诊断保留动作来源位置，输出和映射诊断保留对应主体编号。日志缓冲区保持固定容量，丢弃数量通过运行指标持续可见。

## 运行条件检查

目标程序与 InputWeaver 应处于相同 Windows 完整性级别，通常都以普通用户身份运行。键盘输出按系统输入控制发送，因此最终文本仍由当前键盘布局、输入法、Caps Lock 和修饰键状态决定。

如果激活失败，先读取控制台中的 `code`、`required` 和 `available`；如果运行中触发安全取消，再检查 JSONL 中最早出现的安全诊断、对应来源位置和后续释放记录。出现注入失败、释放缺失或日志丢弃时，应停止当前运行并保留日志文件用于复核。
